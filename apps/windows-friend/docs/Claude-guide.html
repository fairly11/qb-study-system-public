QB STUDY FRIEND · CLAUDE DESKTOP

Claudeに導入と復習セット作成を任せる

1.1.0-preview ／ 2026年10月29日

候補の計算は同梱プログラムが行い、Claudeは起動、QBの画面操作、保存結果の確認を担当します。プログラムだけでも利用できます。

この文書や指示文を受け取っただけで、Claudeの接続・予約・権限が設定されることはありません。本人が内容を読み、対象のPCと自分のアカウントで実行する場合に、指示文をClaudeへ貼り付けてください。
  • 最初に一度だけ準備する
  • 導入を依頼する
  • 毎日の復習を依頼する
  • コマンドから操作する場合
  • 自動実行を予約したい場合
  • Claudeへ渡す範囲
  • 完成の判断

最初に一度だけ準備する

  1. WindowsのClaudeデスクトップアプリを最新版にし、有料プランの自分のアカウントでログインします。Coworkを選べる場合はCoworkで新しい作業を始めます。ChatとCoworkの区別がない新しい画面では、通常の入力欄から作業を依頼します。
  2. Chromeに公式の Claude in Chrome を導入し、自分のClaudeアカウントへ接続します。QB記録用の拡張とは別の拡張です。
  3. Claudeデスクトップの設定で接続機能を開き、Claude in Chromeを有効にします。作業する会話でも、その接続を選びます。画面の名称が異なる場合は公式案内に沿ってください。許可する操作先は本人のQBと、このPCのQB Study Friend操作画面です。
  4. QBへ本人がログインします。パスワード・追加認証・CAPTCHAが必要なときは本人が行います。Claudeに認証情報を貼り付けません。
  5. 配布ZIPを展開し、この docs フォルダーの文書をClaudeが読めるようにします。接続設定後の data フォルダーや、秘密の接続キーを含むファイルは添付しません。

Claudeの作業がクラウドで続いていても、今回使うWindowsのファイル・操作画面・Chromeへ接続するには、PCが起きていて、Claudeデスクトップが開き、ネット接続されている必要があります。これはClaude公式のローカルアクセス条件に基づきます。

導入を依頼する

  1. CLAUDE_SETUP_PROMPT.txt を開き、内容を確認してから全文をClaudeに貼り付けます。同じフォルダーの manual.html も渡します。
  2. Claudeが、このPCのフォルダーやChromeを操作できるか確認します。提供されていない操作機能を、使用できたものとして先へ進めさせないでください。初回の install.cmd・start.cmd 起動は、本人のダブルクリックで行っても構いません。
  3. Notionの空ページと接続の作成は本人のアカウントで行います。接続キーを入力する段階ではClaudeの操作を止め、本人がQB Study Friendの秘密入力欄へ貼り付けます。
  4. 初期設定の保存先をNotionで確認したら、本人が普段の学習として1〜2問を解きます。Claudeには、問題番号・正誤・選択記号・日時・件数だけでPCとNotionの記録を照合させます。

導入が完了しても、Windows実機での記録、Notion送信、日次セット作成はそれぞれ別の確認です。Claudeの報告で「どこまで実際に確認したか」を区別してください。

毎日の復習を依頼する

  1. start.cmd を開き、ChromeのQB Study Friend操作画面を表示します。ClaudeデスクトップとChromeも開いたままにします。
  2. CLAUDE_DAILY_PROMPT.txt の全文をClaudeへ送ります。初回はこの文書も一緒に渡してください。
  3. Claudeは「今日の復習候補を作る」を押し、既存プログラムの結果を使います。独自の問題選定、日次計画の削除、候補の入れ替えは行いません。
  4. ClaudeはQBの問題セット一覧から、表示された名前と番号順のセットを作り、再読み込みして全件を確認します。中断時は同じ計画と同じセットから再開します。
  5. 操作画面への登録・照合が成功した後、Notionの候補ページにも同じQBセットURLがあることを読み戻します。報告されたリンクから本人が復習を始めます。

候補は最大100問です。多い日はブラウザ操作に時間とClaudeの利用枠を使います。途中で利用制限に達した場合も、計画や作成途中のセットを消さず、同じ作業を再開してください。

iPhoneを併用する場合は、候補計算の前にiPhoneの記録が同じ本人のNotionへ届いている必要があります。Windows操作画面の「PCに保存」の件数だけではiPhoneの同期を確認できません。

コマンドから操作する場合

ClaudeがこのWindows上でコマンドを実行できる場合は、review.cmd から同じ操作を行えます。先に start.cmd で操作画面と記録サービスを起動してください。クラウド内の端末で実行しても、このPCのプログラムには届きません。コマンドが使えなければ、前述の画面操作を使います。

まず状態を読むコマンドです。実行するフォルダーは任意です。Windows PowerShellでは、次をそのまま実行できます。

& "$env:LOCALAPPDATA\QBStudyFriend\review.cmd" status

コマンドプロンプト（cmd.exe）では、次の書き方です。

"%LOCALAPPDATA%\QBStudyFriend\review.cmd" status

成功すると、記録の件数と review.day（現在の復習対象日）、準備済みなら review.manifest（セット名と問題番号の計画）を含むJSONが返ります。JSONは項目名と値を組にしたデータです。この操作は状態の読み取りで、QBセットやNotionの行は作りません。秘密の接続キーは出力しません。

以下は続く引数の書式です。YYYY-MM-DD は直前の status が返した review.day に置き換えます。古い日付や例のまま実行しません。ファイルの指定には、そのWindows上の絶対パスを使います。

review.cmd の後ろに付ける引数目的と保存されるもの
prepare YYYY-MM-DDその日の候補を計算し、PCに固定計画と処理記録、Notionに候補ページを保存します。同日計画があれば再利用します。成功結果の対象日・候補・NotionのURLを確認します。
begin YYYY-MM-DD対象セットを作り始める意図をPCへ記録します。この時点ではQBセットは作りません。戻り値の may_create と既存セットの情報を見て、作成または再開を判断します。
remaining "C:\絶対パス\observed.json"QBから読み取った途中の番号列が計画の先頭と一致するか確認し、残りを返します。QBやNotionへの書き込みはありません。不一致なら追加を止めます。
register "C:\絶対パス\verified.json"QBで全件を独立に確認した後、URLと番号を照合し、PCへ照合結果、Notionへセットのリンクを保存します。QBの問題追加そのものは行いません。成功後もNotionを開き直し、同じURLを確認します。

たとえばPowerShellの status の末尾を、対象日を指定した prepare YYYY-MM-DD に置き換えて使います。本人の一時作業フォルダーに、Claudeが実際の読み取り結果だけで次の入力ファイルを作ります。data や設定ファイルは直接変更しません。

  • remaining 用：{"day":"対象日","ids":["QB上で確認した番号", "次の番号"]}。ids は表示順の配列です。
  • register 用：{"day":"対象日","url":"同じQBセットの検索画面URL","ids":"番号を改行で区切った文字列","confirmed":true}。confirmed は全件を実際に確認したときだけ true にします。

上記のJSONは形の説明です。文字どおりの「対象日」「番号」や、架空の問題番号を本番へ渡しません。作業用JSONに必要なのは対象日・安全な問題番号・セットURLだけで、Notionキーやセッション情報は不要です。キーの読み取りはプログラム内部で処理されるため、Claudeが session.json や接続キーファイルを直接読む必要はありません。

自動実行を予約したい場合

まず本人が見ている状態で、候補計算からQBセット作成・Notionの読み戻しまで一度成功させてください。その後に、Claude側で定期実行を設定します。ZIPのインストールだけでは予約を作りません。

現行のClaudeでは、Coworkの /schedule または予定の管理画面から予約を作れます。利用中のプラン・組織設定・画面でこの機能が使えるか確認してください。公式説明のクラウド予約と、Windowsのローカル処理に接続できることは別です。

  1. 同じClaude作業に日常運用の指示文を保存します。
  2. 本人の指示で、日本時間の毎日04:00に候補計算とセット作成、07:00に同日の完成確認を予約します。両方とも同じ日次計画と同じQBセットを使い、07:00に新しいセットを作りません。
  3. 予約の管理画面で、保存された時刻・タイムゾーン・指示内容を読み直します。「予約する予定」という返答だけでは設定済みにしません。
  4. 実行時間にPC・Claudeデスクトップ・Chrome・記録サービスが使えるようにします。PCがスリープ中、接続が切れている、QBの認証待ちなどで操作できない場合は、完了を保証できません。保護設定の解除は必要ありません。
  5. 初回の予約実行後、QBセットの実在とNotionのリンクを確認します。PCが使えず未実行だった場合は、その日の保存済み計画から再開します。過去の未実行日をまとめて生成しません。

autostart-on.cmd はログイン時に記録サービスを起動する機能です。Claudeの定期実行やPCのスリープ解除を設定するものではありません。

Claudeへ渡す範囲

使ってよいもの渡さないもの
同梱手順、復習候補の問題番号、セット名、件数、URL、保存結果の確認用コードNotion接続キー、パスワード、Cookie、セッションファイル、設定済みの data フォルダー
QBの公開画面上のセット作成・追加・番号照合QBの問題文、選択肢本文、解説、画像、非公開APIの解析

対象外のセットや過去の学習履歴は変更しません。操作結果が不明なときは、読み戻しで状態を確定してから続けます。自動承認やOSの制限で拒否された場合は、別経路で回避せず、拒否された操作と理由を報告させてください。

完成の判断

完了は、次の3点が揃った場合です。候補計算だけ、追加ボタンを押しただけ、ローカルの成功表示だけでは完了にしません。

  1. 日次計画の問題番号と順序が固定されている。
  2. QBセットを再読み込みし、全ページの問題番号・件数・順序・重複・欠落が計画と一致する。
  3. 照合後、Notionの候補ページにも同じQBセットのリンクが保存されている。

候補0問の場合は、Notionの「候補なし」のページを確認して完了です。毎回の報告は「完了／途中」「対象日と件数」「QBとNotionのリンク」「本人の操作が必要ならその1点」に絞ります。
