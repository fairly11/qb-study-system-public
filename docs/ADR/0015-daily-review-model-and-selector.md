# ADR-0015: 日次復習候補と暫定FSRSモデルを分離する

- 状態: 採用
- 決定日: 2026-10-16
- 更新日: 2026-11-11（選択器の版5）

## 対象と前提

各端末からNotionに届いた解答履歴を使い、その日に取り組む復習候補と選定理由を計算する。
元のAttemptEventV1、HistorySnapshotV1、通常演習と復習の分類は上書きしない。
このADRは純粋計算を扱う。Notion取得、当日計画の固定、公開、QB問題セットへの反映は呼び出し元が担う。

## 入力と計算時点

`generateDailyReviewPlan` は明示された `as_of` と証拠だけを使用する。
現在時刻、保存先、ネットワーク、乱数を計算中に参照しない。
通常は04:00 JSTを `as_of` とし、Mac停止などで実行を逃した場合は再開時点を明示して計算する。
`target_date` は直前の04:00 JSTが属する日、日次実績の `calendar_date` は `as_of` の東京暦日とする。
当日の計画を一度保存した後に入った履歴で、候補を入れ替えない責任は呼び出し元にある。

版3以降では、`target_date` の翌04:00 JST未満にモデル上の復習期限が来る問題を候補に含める。
計画の任意フィールド `due_before` は、この排他的な上限をUTCの時刻として保持する。
翌03:59:59.999は含め、翌04:00ちょうどは含めない。
遅延実行や日付をまたいだ再開でも、範囲の終わりは対象日の翌04:00のままとする。
入力証拠の取得期限とモデルの予測基準時刻は `as_of` から変えない。
これにより、朝には未到来でも同じ復習日の午後や夜に期限を迎える問題を、固定の日次セットへ含められる。

同じevent_idの同内容は一件として扱う。内容が衝突した場合は停止する。
日時のoffsetと選択肢配列順は正規化し、同時刻の別解答はevent_id順で決定的に処理する。
`answered_at` または `provenance.recorded_at` が計算時点より未来の解答は除外し、除外件数を返す。
snapshotも観測時点より前のものだけを別枠で保持する。
snapshotの回数や最終状態を、個々の解答、時刻、FSRS評価へ変換しない。

通常演習、復習、分類不明について、解答回数と異なる問題数を別々に集計する。
分類が欠けた解答を問題番号から復習と推定しない。
どの分類の正誤も記憶計算へ入力するため、通常演習の成果も次回計算に反映される。
同期開始前の既存記録はNotion同期開始時の除外境界があるため、この機能の導入で自動的に再送・統合しない。
共有原本へ到着していない解答がある場合、「全履歴が揃った」とは扱わない。

## 予測モデル

`ReviewMemoryModel` と候補選択器を別にし、予測モデルを交換・比較できるようにする。
記憶モデルは `ts-fsrs` 5.4.2を固定して使用する。
この版はFSRS-6を実装する。依存更新時はモデル版を更新して比較する。
乱数による間隔調整を無効にし、短期の分単位学習ステップは無効にする。

観測した `correct` は暫定的な `Good`、`incorrect` は `Again` として計算する。
`unknown` は実績に残すが記憶状態を更新しない。
実測正誤と派生評価は、出力の別フィールドに保持する。
この対応は利用者が入力した難易度評価でも、正解できる確率の実測値でもない。

`request_retention` の初期値0.9は暫定設定であり、個人に最適化された値ではない。
0より大きく1未満の値で変更できる。変更値と設定版、設定のハッシュを保存する。
個人パラメータの学習や、DAS3Hによる知識成分の推定は行わない。
予測確率はこの暫定モデルの値として表示する。

正誤のある解答がゼロなら `insufficient`、初期値では3解答未満または2日未満なら `partial` とする。
これらの閾値は設定可能である。
`sufficient` はこの履歴量条件を満たしたという意味に限り、モデルの個人精度を保証しない。
全状態の `model_status` は `provisional` のままとする。

## 候補選択

候補は第116回〜第120回の国試問題から最大100問を選ぶ。
対象範囲は年に応じて自動変更しない。候補が少ない場合も範囲外の問題で埋めず、未着手分を翌日の上限に加算しない。
これは復習候補の上限であり、通常演習の回数を差し引く一日の総演習予算ではない。
対象範囲外の履歴は保持し、候補からの除外理由を `outside_exam_scope` として記録する。
範囲内の問題には次の条件を適用する。

1. 利用者が停止した問題を除外する。
2. 計算時点の東京暦日に正答した問題を除外する。
3. 全分類を合計した同日解答回数が問題別上限に達した問題を除外する。初期上限は2回。
4. 利用者指定の復習日が未来なら前倒ししない。指定日はモデル予測と分離して保持する。
5. 手動指定の期日到来、モデル期限が `due_before` 未満、または同日不正解の再試行対象を候補とする。

モデル期限の拡張で、日付だけの手動指定を前倒ししない。
日付だけの補完履歴も時刻へ変換せず、既存の日付単位の期日判定を維持する。

同日再試行は、その日まだ解いていない候補より低い優先度にする。
それ以外は手動期日到来、直近不正解、通常のモデル期日到来の順に並べる。
同じ優先層では、利用可能な分類が偏らないよう、選択済みが少ない分類を先にする。
実際の知識タグがあればその先頭タグ、なければ科目と分野の先頭値を安定した分類キーとして用いる。
複数値は辞書順で正規化する。この簡単な分散は知識成分の推定ではない。
同じ分類数の場合、版5では下記の回別補正を加えた忘却リスク、モデル期日、問題キーで順序を決める。

理由は固定コードと事実の組を返す。実測されていない「苦手」「忘れた」などを断定しない。
たとえば手動期日、モデル期日、直近の不正解時刻、当日の解答回数、履歴不足の件数を保持する。
版3の `model_due` 理由には `model_due_at`、`as_of`、`due_before` と `due_window` を残す。
`due_window` は選定時点ですでに期限が来ている `overdue` と、その後の日内期限 `later_in_review_day` を区別する。
計画出力は既存ReviewPlanV1を書き換えない独立した `review-plan-v2` DTOである。
呼び出し元が計画IDを付与し、追記専用で保存する。
証拠ハッシュ、設定ハッシュ、選択器版、モデル版、評価変換版を残し、後から同条件を再計算できるようにする。

`due_before` のない旧計画も読み込めるようにする。
版3では翌04:00までの期限範囲、版4では116〜120回への範囲制限、版5では第120回の重み付けを追加した。
新規計画の `algorithm_version` は `5` とし、旧計画の照合には保存済みの版を使う。
旧計画を自動で移行または再選定しない。
当日分の追記を明示的に実行した場合だけ、`selectDailyReviewAdditions` が保存済み状態の `not_due` から期限範囲に入る問題を返す。
停止など別の除外条件を緩めず、元の問題を除いた残枠まで選び、元の問題数に続く位置番号を付ける。
戻り値の `eligible_question_count` は、残枠を適用する前の追加候補数である。
この関数は保存済み計画、元証拠、予測結果を変更しない。追記の保存と公開はADR-0016に従う。

## 第120回の重み付け（2026-11-11、版5）

復習期日や科目の配分を維持しながら、第120回の問題を優先するために回別の重みを設ける。
係数1.25は運用上の設定であり、出題確率や学習効果から推定した値ではない。

2026年11月11日の仕様変更以降、新規計画は選択器の版5を使う。
手動期日、直近不正解、通常候補、同日再試行の優先分類と、科目・分野の配分は維持する。
その条件が同じ候補では、忘却リスク（1−モデルの予測想起率）を第120回だけ1.25倍にして、高い順に選ぶ。
同じ補正値なら第120回を先にし、その後は従来のモデル期日と問題番号の順とする。
予測想起率が不明な場合は数値を作らず、従来どおり比較上のリスクを0とし、同順位のときだけ第120回を優先する。
記憶予測、復習期限、候補の除外条件、116〜120回の固定範囲、上限100問は変えない。
50%などの回別固定枠は設けず、期限前の問題で補充しない。候補が100問以下なら主に並び順、上限を超える場合は選抜にも影響する。
選定理由には `exam_priority_weight` と補正係数を保存し、Notionにも表示する。
保存済み計画とセット、旧計画への明示的追記は、元の順序と計算方式を保持する。

重みは新規生成が共通選択器へ `exam_weighting: "exam120_v1"` を明示したときだけ有効にする。
未指定の比較は旧式そのままを維持し、旧追記の再計算とハッシュ照合へ影響させない。
版5は独立したreview-plan-v2の選択器版で管理し、既存V1契約や履歴の形式は変更しない。

## 検証と限界

ユニットテストで重複、内容競合、通常/復習/不明集計、未来除外、04:00境界、snapshot分離、停止、手動日付、同日正答除外、回数上限、候補上限、分類分散、決定性、設定変更、モデル交換を確認する。
期限範囲の拡張は、翌04:00の排他境界、月や年をまたぐ日付、遅延実行、未来証拠の非混入、通常学習の正解、既存除外の維持を検証する。
追記候補は、元計画の不変、先頭の保持、残枠上限、重複除外、決定性を検証する。
日次計画の固定と公開時の多重作成防止はサービス層の別テストで確認する。
他のMacの未送信履歴、公開先の更新状況、実際の学習成果は計算テストでは検証できない。
