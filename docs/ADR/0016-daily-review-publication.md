# ADR-0016: 日次候補の固定と問題セットの照合

- 状態: 採用。学習目的の判定は [ADR-0017](0017-automatic-qb-capture.md) で変更

日次候補は通常学習のノルマと分離し、最大100問を優先順に固定する。
利用者は途中で止められ、翌日は実解答履歴から選び直す。
セットを作成しただけでは解答済みとせず、実際の解答を進捗へ反映する。
予測モデルと選択の設計はADR-0015を参照する。

## 解答と学習区分の保存

AttemptEventV1は変更せず、StudyContextV1を別証拠として追加する。
新規送信はv2のenvelopeでattemptとcontextを同時保存する。
旧v1記録は未分類とし、後から目的を推測して書き換えない。
当初は拡張機能の画面で学習目的を選択する方式とした。
現在はADR-0017に従い、復習セットの照合による自動判定と、演習中の手動選択を使用する。

Notionは複数Mac共通の原本であり、毎回全ページを取得する。
集計除外の記録は予測と件数から除く。
不正な行や不明な分類は件数で明示し、履歴表示から個々の解答を推測して追加しない。
問題マスターの復習停止と手動復習日を読み、変更しない。

## 日付

候補更新はAsia/Tokyoの04:00を境界にする。
実行が遅れた場合は実行時点までの履歴で最新の対象日だけを作る。
通常学習と復習の当日件数は日本時間00:00を境界に集計する。
両者を同じ日付概念として扱わない。
選択器の版3は対象日の翌04:00 JST未満に到来するモデル期限を含める。
履歴と予測の基準時刻は実行時点までとし、当日の候補は保存後に自動で入れ替えない。

## 公開

公開担当は設定に記載した1台のMacに限定する。
ローカルのdaily-reviewフォルダには計画と操作の意図・結果を追記専用で保存する。
同日計画が存在すれば再計算せず、足りない派生ファイルだけを復旧する。
計画本体と照合用データはNotionの日付別ページにも保存する。

NotionページやQBセットの新規作成前に意図を保存する。
応答を失った場合は既存のページまたはセットを照合する。
確認できないときは新規作成を止める。
単一Macの排他制御は別Macとの分散ロックを代替しないため、公開担当を複数にしない。

QBには公開画面から優先順位の順に1問ずつ追加し、追加日の古い順にする。
まず5問以下で保存先と順序を検証し、最後に全件を独立して読み戻す。
連問で追加された問題は予定にない問題として検出する。
上限や順序を守れないセットを完成扱いにしない。

## 当日の完成済みセットへの追記

当日の完成済みセットへ問題を追加する操作として、`amend-day` を設ける。
実行には対象セットへの追記の明示的な指定を必要とし、版3で導入した期限範囲を適用する。
通常の `prepare` や日次自動実行から追記を作らない。
過去の日に新しい追記を作ることも許可しない。
対象は現在の最新04:00が属する日で、元のQBセット、全件照合、Notionページ、セットリンクが確認済みの旧計画に限る。

元の `plan` と `manifest` は保持し、`revision-1` と `manifest-revision-1` を追記専用で保存する。
revisionには元計画のハッシュ、追記時刻、理由、同じQBセットURL、追記後の計画を保持する。
元の解答履歴、集計、証拠ハッシュ、設定、予測を再計算しない。
保存済みの `not_due` から翌04:00未満の期限に該当する問題だけを追加し、元itemsを完全に同じ先頭部分として残す。
たとえば元の4問は先頭4問のままで、追加問題は5問目以降となる。上限100問は追記後の合計に適用する。

追記後の操作は有効計画とmanifestを参照し、同じQBセットへ不足分だけを追加する。
全件照合は `qb-verified-revision-1` に別記録として保存し、元の照合結果は変更しない。
`link-set` はQBの追記後照合を前提に、既存Notionページの元計画とリンクを残したまま追記節を公開する。
Notion側は元計画との連結、内容ハッシュ、同じ計画IDと日付、同じセットURL、元itemsの完全な先頭一致を検証する。
QBとNotionの両方で追記後の内容を照合できるまでは完了と扱わない。

Notion追記の前に操作意図を保存する。応答が不明な場合は既存追記の照合だけを行う。
存在しないように見えることだけを根拠に再追記しない。
明確に拒否されたことが記録され、再試行可能な応答であった場合だけ、指定待機時間後に次の追記試行を許す。
途中停止後も、元計画や操作意図を削除してやり直さず、保存済みrevisionから再開する。

## 実行の境界

計画の取得・保存・照合はCLIで実行し、QBへの登録はログイン済みブラウザの画面操作で行う。
定期実行する場合は、CLIと画面操作を呼び出す実行環境を別途用意する。
非公開APIやブラウザの内部保存情報は使わない。
実行するMac、Notion接続、QBのログイン状態が必要で、Macの自動起動設定はこの処理に含めない。
スケジュールが実行されなかった日は、次に実行できた時点の最新日だけ処理する。
