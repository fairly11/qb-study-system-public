# ADR-0017: 自動記録と学習区分の判定

- 状態: 採用
- 決定日: 2026-10-18
- 更新日: 2026-10-31
- 置換対象: [ADR-0012](0012-browser-extension-qb-capture-consent.md) のページごとの開始操作、[ADR-0016](0016-daily-review-publication.md) の学習目的の選択方式

## 背景と決定

問題へ移動するたびに開始操作を求めると、記録の開始忘れが起きる。
問題画面に入ったら自動で実解答の記録を始め、通常学習と復習の区分も可能な範囲で自動判定する。
利用者は演習中に一時停止したり、学習区分を手動で選んだりできる。
解答操作の代行や、過去の結果表示からの記録作成は行わない。

## 画面移動への追従

QBではセット画面から問題画面への移動が、文書を読み直さずに行われることがある。
そのため、URLを確認する小さなスクリプトをQBの同一HTTPSオリジン全体へ配置する。
Navigation API、履歴イベント、1秒間隔のURL確認で画面移動を検知し、解答の監視は正確な `/quiz` かつ最上位フレームでのみ開始する。
演習への再入場には新しい記録セッションを発行し、前の演習の通知や再送と混ぜない。

ChromeのタブURL読み取り権限は追加しない。
Chromeが通知した送信元のorigin、フレーム、`documentId` を確認したうえで、その文書へ現在の画面情報を問い合わせる。
画面側が返す情報は、画面種別、セットID、問題ID、セットIDの妥当性に限定する。
検索語などのクエリ、URL全文、問題本文は通知しない。

Chromeの `sender.url` は文脈作成時のURLを保持するため、文書内での移動後も最初の検索画面を示すことがある。
この値だけで現在の問題画面を認証しない。
根拠となるChromiumの実装は [メッセージ送信](https://raw.githubusercontent.com/chromium/chromium/main/extensions/renderer/ipc_message_sender.cc)、[URLの保持](https://raw.githubusercontent.com/chromium/chromium/main/extensions/renderer/script_context.cc)、[URL変更時の扱い](https://raw.githubusercontent.com/chromium/chromium/main/extensions/renderer/script_context.h) を参照する。

一時状態の読み取り前と書き込み直前に、同じ `documentId` の画面情報を照合する。
遅れて届いた検索画面の通知で、新しい演習や別セットの情報を上書きしないためである。
新形式の通知に文書IDがなければ拒否し、旧形式の通知には従来のURL完全一致による確認を維持する。

記録開始と解答候補は、確認済みの問題画面、文書ID、記録セッションID、現在も問題画面にいることを組み合わせて検証する。
同じ演習内の次問通知が応答待ちでも、初回確認済みのセッションは維持する。
初回確認前、別文書、別フレーム、別origin、問題画面からの退出では解答候補を受け付けない。

## セットの由来

セットURLの `questionSetId` は、演習開始後の `/quiz?question_id=...` には残らない。
移動元のセットIDをタブ単位の一時状態へ保持し、同じ演習へ引き継ぐ。
新しい文書へ移る場合は、同じ問題の再読み込みか、直前セットと一致するQB内の参照元を確認した場合だけ引き継ぐ。
保存するのはセットID、文書ID、画面種別、直前問題IDであり、参照元URL全文ではない。

収集サービスの `GET /v1/review-sets/<ID>` は、作成と照合が完了したローカルの操作記録、または共通Notionの計画データと確定リンクを調べる。
拡張からの問い合わせ先は同じ端末の収集サービスに限定し、Notionの接続キーを拡張へ渡さない。
問題番号の一致、セット名、並び順だけでは復習と判定しない。

## 学習区分

新しい解答には次の規則を適用する。

| 条件 | 学習区分 |
|---|---|
| 確認済みの復習セット | `review`。照合した計画IDを付ける |
| 復習セットではないことを確認済み | `normal` |
| 正当な問題画面で、セットの由来がない・失われた | `normal` |
| セット照合の通信失敗や不正なセットID | 判定未確認として扱う |
| 送信元の検証に失敗 | 解答を受け付けない |

記録の監視は照合の完了前に開始し、最初の保存処理は区分判定の結果を待つ。
分類の通信待ちは、他タブの開始や一時停止を止めない。
受信時点で送信元を確認できた解答候補は、待機中に画面を離れても元の演習として保存する。
確定した区分は送信待ち、再送、背景処理の再起動を通して保持する。

「通常学習」「復習課題」を選ぶと、現在の演習で以後に解く問題へその区分を使う。
遅れて返った自動判定で手動選択を上書きしない。
手動選択のために記録を停止・再開したり、表示済みの結果を追加したりしない。
別タブや別演習には持ち越さず、手動で復習を選んだ場合の計画IDは推測しない。
保存済みの解答と送信待ちの区分は変更しない。

## 判定未確認からの再開

記録中の確認済みセッションは、30秒間隔で開始通知を再送して背景処理の状態を回復する機会を作る。
停止中は再送せず、一時停止を自動解除しない。
検索画面での照合が未分類で終わった場合、その結果はキャッシュに残さず、演習開始時に再度照合する。

Chromeで記録中の未分類は、65秒、130秒、260秒、以後最大5分の間隔で再照合する。
待機中の解答は受信時点の未分類で保存する。
後から復習の由来を確認できた場合は、それ以後の新しい解答にだけ確定した区分を使う。
Safariの保存と分類待ちは [ADR-0019](0019-ios-safari-recording.md) を参照する。

## 解き直しと結果の再表示

未解答から結果表示への遷移を記録する。
次問の番号が前問の結果より先に表示されても、その表示だけで次問を処理済みにしない。
一度表示された結果へ戻る場合は、新しい解答操作を確認するまで候補化しない。

解答操作の確認は、「解答する」というラベルの有効なボタンへの、ブラウザ由来の `isTrusted` クリックを使う。
ボタンの位置は、空の `DIV`、`div.grid.grid-cols-3.p-1.py-3`、同じ問題の `div.flex.flex-col.gap-2` という親子関係で検証する。
同時点の未解答状態、問題番号、選択状態が一致することも確認する。
選択肢本文は読まず、クリックを実行・変更・キャンセルせず、クリック履歴も保存しない。
確認した操作を別問題、一時停止後、退出後へ持ち越さない。

## 更新と制約

拡張を更新するときは読み込み元を維持し、拡張と既存QBタブを再読み込みする。
削除・再インストールで送信待ちを失わないようにするためである。
更新後の通常のサイト内移動では、拡張を起動するための再読み込みは不要になる。
既存V1とデータベース形式を維持し、計画IDには `StudyContextV1` の任意項目を使用する。

拡張は問題セットの順序や内容を変更しない。
停止中に表示された解答を、再開後に遡って記録しない。
保存処理に渡す前にページを閉じた場合や、未対応の画面構造では記録できないことがある。

## 検証

合成画面と模擬Chrome APIで、文書内移動、連続解答、初期表示、再表示、停止と再開、通信失敗、古い通知、手動選択を検証する。
送信元URLを初期の検索画面へ固定したケースと、画面通知が遅れるケースも対象にする。
実機と本番サービスでの確認範囲は [検証記録](../VALIDATION.md) を参照する。
