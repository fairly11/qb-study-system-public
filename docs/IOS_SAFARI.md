# iPhone / iPad用QB記録の導入と確認

Safariの解答記録をiPhoneやiPadに保存し、Notionへ同期するための導入手順です。
iOS / iPadOS 16.4以上をビルド対象とし、iPhoneとiPadで同じ取得・保存・同期処理を使います。
開発時の検査は [検証手順](IOS_SAFARI_VALIDATION.md) を参照してください。

## 記録と保存状態

Safariで実際に解答を確定すると、問題番号、日時、正誤、選択記号を保存します。
同じ問題を解き直した場合は別の記録にし、閲覧や過去の結果表示だけでは記録を作りません。
QBの問題文、選択肢本文、解説、画像は保存しません。

最初にSafari拡張内へ保存し、次にアプリと拡張の共有領域へ転送します。
アプリ側の保存完了を受け取るまでは、Safari側の送信待ちを残します。
Notionへの送信後は、同じイベントIDと内容を読み戻して確認します。
Macの起動や同じWi-Fiへの接続には依存しません。

| 表示 | 意味 |
|---|---|
| 保存処理中（未確認） | 保存完了をまだ確認できていない |
| Safari保存済み・アプリへ転送待ち | 拡張内には保存済み。アプリ側への転送待ち |
| 端末保存済み・Notion送信待ち | 端末のSQLiteへ保存済み。Notionからの確認前 |
| Notion確認済み | Notionから同じ記録を読み戻し、一致を確認済み |
| 保存失敗 | 保存済みと扱わず、画面上で再試行する状態 |

iOSがバックグラウンド処理を停止する場合があるため、常時即時同期は保証しません。
Safari内だけに残った転送待ちは、QBへの再入場や拡張画面を開く操作で再開します。
アプリ側へ保存済みの記録は、管理アプリの起動でもNotionへの送信を再開できます。
管理アプリだけでは、Safari内のみに残っている記録を取り出せません。

保存が完了する前にタブやアプリを終了すると、記録できない場合があります。
失われた解答を推測して追加する機能はありません。
保存失敗の表示がある場合は、保存完了を確認してから画面を閉じてください。

## ビルドと署名の準備

MacにXcodeとiOS向けの開発部品を用意し、Xcodeの初回準備を完了してください。
プロジェクト直下で依存関係を取得し、Safari拡張のファイルを生成します。

```sh
pnpm install --frozen-lockfile
pnpm build
```

**署名**：アプリの作成者と実行を許可する端末を、Appleの仕組みで確認する設定です。
**App Group**：管理アプリとSafari拡張で、同じ端末の保存領域を共有するための識別子です。

1. Xcodeで `apps/ios-safari/ios/QBRecord.xcodeproj` を開きます。
2. `apps/ios-safari/ios/Config/Local.xcconfig.example` を同じフォルダへ `Local.xcconfig` としてコピーします。
3. コピーしたファイルに、自分のBundle識別子、App Group識別子、Team IDを設定します。Notion接続キーは書きません。
4. 管理アプリと拡張の両方を同じTeamで署名し、同じApp Groupを有効にします。仮の識別子のまま実機導入へ進めないでください。
5. 接続したiPhoneまたはiPadを実行先として選び、端末で必要な開発者モードと信頼設定を済ませて起動します。
6. 端末のSafari拡張設定で「QB記録」を有効にし、`qb.medilink-study.com` へのアクセスを許可します。

iPhoneとiPadの実行許可は、それぞれの端末について確認します。
署名の有効期間や更新方法は、利用するAppleアカウントの条件に従います。

既存のアプリを更新する場合は、Bundle識別子、App Group、Keychainの共有設定を保持してください。
識別子を変えたりアプリを削除したりすると、既存の記録や設定を引き継げない場合があります。
送信待ちの記録を確認する前に、アプリを削除しないでください。

## Notionへの接続

[Notion同期の仕様](NOTION_SYNC.md) に従った解答ログ、問題マスター、復習計画の親ページを用意します。
iPhone / iPad版は既存の保存先を使用し、既存の解答行を変更・削除しません。
Macと共通の履歴として使う場合は、Mac側もSafari由来の記録を読み取れる版を使用してください。

接続先には次の条件が必要です。

- 「記録元」の選択肢に `Safari拡張` があること。
- `記録データV1` と `学習目的データV1` が所定のテキスト型であり、「問題」が正しい問題マスターに関連付いていること。
- 「学習種別」の選択肢に `通常学習`、`復習`、`未分類` があること。
- Notion接続に、対象表と復習計画の親ページの読み取り、および解答ログと問題マスターへの追加権限があること。

管理アプリへ、解答ログのデータソースID、問題マスターのデータソースID、復習計画の親ページID、接続キーを入力します。
データソースIDは表の識別子であり、ページIDやdatabase_idとは異なります。
接続キーはアプリの秘密入力欄へ入力します。

「接続を確認して保存」は接続先の構造を読み取り、学習記録を作らずに設定を検査します。
成功後、接続キーは端末のKeychainに保存し、JavaScriptやQBページへ渡しません。
誤った表への送信を避けるため、二つのデータソースIDは初回保存後に変更できません。
復習計画の親ページIDと接続キーは更新できます。

設定は端末ごとに必要です。
iPhoneの設定や送信待ちがiPadへ自動転送されるわけではありません。

## 通常学習と復習の判定

Safariで観測したセットIDを、Notionの計画と確認済みのセットリンクへ照合します。
セット名や問題番号の一致だけでは復習にしません。
確認済みの復習セットは「復習課題」とし、通常の演習や問題への直接移動は原則「通常学習」にします。
既知のセットの照合が未完了、通信障害、親ページ未設定などで判定できない場合は、判定未確認のまま保持します。

拡張画面の「通常学習」「復習課題」で区分を選ぶと、現在の演習の以後の解答へ適用します。
保存済みや送信待ちの解答、過去の未分類記録は変更しません。
手動選択を後から返った自動判定で上書きしません。
手動で復習を選んでも、計画IDを推測して付与することはありません。

計画が多い場合は、照合済みの情報と再開位置を端末に保存して読み取りを続けます。
途中までしか読めていない状態を「復習に該当しない」とは扱いません。
解答は端末に保持し、照合と送信を後で再開します。

## 端末で確認する項目

最初に、署名、Safari権限、App GroupとKeychainの共有、接続先の読み取りを確認します。
記録の確認には普段の学習で行った解答を使います。

| 操作 | 確認すること |
|---|---|
| Safariで演習へ移動して解答する | 番号、記号、正誤、日時と保存状態が一致する |
| 同じ問題を実際に解き直す | 別の解答記録になる |
| 結果画面の再表示や再読み込み | 解答操作なしで記録が増えない |
| 通信を切った状態で解答する | 端末保存済み、送信待ちになる |
| 通信復帰後にQBまたは管理アプリを開く | 元のIDで送信を再開し、Notionに重複しない |
| 確認済みの復習セットから解答する | 復習と計画IDを照合できる |
| 学習区分を手動で変更する | 以後の解答だけに適用し、過去記録を変えない |
| iPadを回転またはサイズ変更する | 設定欄と保存状態を操作できる |

端末のロック、長時間のバックグラウンド、強制終了からの復帰時の挙動は、使用する端末で確認してください。

## 停止と復旧

| 状態 | 確認すること |
|---|---|
| `NOTION_CREATE_UNCONFIRMED` | 送信結果が未確定。同じIDを読み戻して確認し、見つからないだけで再作成しない |
| `NOTION_SCHEMA_MISMATCH` | 列、選択肢、関連先が想定どおりか確認する |
| `NOTION_UNAUTHORIZED` / `NOTION_FORBIDDEN` | 接続キーと対象への権限を確認する |
| `APP_GROUP_UNAVAILABLE` / `KEYCHAIN_UNAVAILABLE` | 署名、共有設定、端末ロック状態を確認する |

復旧のために送信待ち、元の解答、イベントIDを消さないでください。
記録を止める場合はSafariの拡張を無効にします。
拡張を無効にしても端末内の記録は残ります。
